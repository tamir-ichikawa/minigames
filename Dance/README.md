# DDE — ダンスダンスエボリューション

佐藤さんの [DDE v0.3](https://hhoshizora-usagi.github.io/eed/) を、Phaser 3.90 + TypeScriptで再構築したゲームです。2曲・6譜面、4方向の操作、上下スクロール、100万点満点、ベスト記録を引き継ぎました。元の配信サイトや原本は変更していません。

## 遊ぶ

プロジェクトのルートで実行します。

```sh
npm run dev:dance
# http://127.0.0.1:4176/Dance/
```

単独開発サーバーでは編集後にコマンドを再実行してください。共通開発サーバー `npm run dev` は変更を監視します。

```sh
npm run build
npm run preview
# 単独: http://127.0.0.1:4173/Dance/
# 一覧から: http://127.0.0.1:4173/play.html?game=dance
```

配布は `dist` の内容を使用します。`Dance/index.html` の直接ダブルクリックは対象外です。`dist/Dance` は単独でもHTTP配信できます。インターネット上のCDNや元のサイトには依存しません。

PCは矢印キー、または D / F / J / K。スマートフォンは該当するレーンをタップします。異なるレーンの同時入力に対応しています。キーの押しっぱなしでは連打になりません。通常は下から上、リバースは上から下に流れます。

## ファイル

- `original/index.html`: 2026-10-20取得の原本をそのまま保存。
- `assets/*.mp3`: 原本の埋め込み音声を無変換で取り出したもの。
- `songs.json`: 2曲の情報と6譜面。時刻・レーン・表拍/裏拍を保存。
- `index.ts`: 選曲、入力、画面配置、保存、共通プレイヤーとの連携。
- `scene.ts`: Phaserによるレーン、矢印、判定、背景の描画。
- `alignment.ts`: MP3デコード差を短い音声署名から自動補正。
- `audio.ts`: 音声の読み込みと出力時刻、停止、再開、消音。
- `rhythm.ts`: フレームレートに依存しない判定とスコア計算。
- `style.ts`: 縦・横の配置とUI。
- `build.mjs`: 単独・共通ビルド。
- `../games/dance/`: 共通一覧の登録情報。
- `../tests/dance.test.mjs`: 譜面・判定・音声時計・再開競合の回帰検証。

## タイミングの確認と修正

原本の音声と譜面を比較したところ、半拍グリッドからの譜面の逸脱はなく、曲の後半に向けた大きなドリフトも検出しませんでした。波形の立ち上がりは帯域・音色によって異なるため、一律の譜面オフセット変更は行っていません。

| 曲 | 原本BPM | 譜面の基準時刻 | 全帯域の立ち上がりピークとの差 |
| --- | ---: | ---: | --- |
| DIGITAL STAR | 149.99 | 0.498秒 | 区間平均で約 +6〜8ms |
| RISING HIGHER | 120 | 1.600秒 | 区間平均で約 +4〜8ms |

解析は32kHz音声に1024サンプルの窓、128サンプル間隔で正のスペクトル差分を計算。12〜45秒、45〜90秒、90〜135秒、135秒以降を比較しました。数値は知覚上の正解を断定するものではなく、約4ms刻みの分析に基づく拍グリッドの整合性確認です。低域のピークは約12〜20ms遅く、発音の立ち上がり方の差も含みます。

ブラウザーの `AudioContext` で展開したPCMとの追加照合では、両曲とも基準PCMより約18ms早く始まる固定差を検出しました（44.1kHzの検証環境）。そこで曲の12〜16秒の音量変化を1ms刻みの署名として保存し、実際に展開した音声と照合して、譜面の時計を補正しています。32 / 44.1 / 48kHzで同じ処理を使い、固定のブラウザー名や一律の補正値に依存しません。相関が0.98未満のときは推測による補正を行いません。原本の音声・譜面の値は維持しています。

修正内容:

1. `AudioContext.currentTime` の変化から独自に時刻を補間する処理を廃止。`getOutputTimestamp()` で音声の出力時刻と画面・入力時刻を結び付けます。出力タイムスタンプがない場合は基礎遅延と出力遅延を考慮した音声時計を使用します。フレーム時間の加算で曲の時刻を進めません。
2. キー／ポインターを押したイベント時刻で判定します。古いWebKitのエポック形式にも対応。通常の遅延イベントには100msのMISS確定猶予を設けました。
3. 同じレーンの判定範囲が重なるとき、古いノートを優先する処理から、入力時刻に最も近いノートを選ぶ処理に変更。
4. 一時停止・タブ非表示時に音声と判定を止めます。非同期の音声再開を中断と誤認しないようにし、共通プレイヤーの停止とゲーム内の停止を分けて管理します。
5. MP3の先頭処理の差を音声署名から自動補正し、音声ファイルを大きなWAVに置き換えずに同期を維持。
6. 読み込み失敗から再試行でき、音声の再開が完了してから演奏を始めます。全曲の末尾まで再生して結果に進みます。

PERFECTは±45ms、GREATは±90ms、GOODは±135msで原版と同じです。各判定の点数比率は1 / 0.6 / 0.2 / 0。タイミング調整は±300ms、5ms刻み。＋は音が遅れて聞こえる機器に合わせて表示・判定を遅らせます。Bluetooth機器固有の遅延は実際の端末で調整してください。原版の記録キーは上書きせず、本移植の記録と設定は `dance:*:v1` で保存します。

## 画面サイズ

縦画面は520×900、横画面は1000×600を論理サイズとして、利用可能な親領域に同率で拡大縮小します。縦横比に応じた余白は許容し、画面や操作ボタンを切り落としません。`100dvh`、safe-area、`ResizeObserver`、任意の全画面切り替えに対応しています。

画面の向きを変えても、再生中の曲、判定済みノート、スコア、コンボは維持します。表示上のレーンの長さだけが変わり、判定は音声の時刻を参照し続けます。ゲーム本体のリサイズは曲の再読み込みや再スタートを行いません。

## 検証

```sh
npm run test:dance
npm run typecheck
npm test
npm run build
```

[検証記録](checks/verification.md) にブラウザーでの確認結果を記載しています。

音声解析を再現する場合は、原音をPCM WAVにデコードして `/tmp/dance-digitalstar.wav` と `/tmp/dance-risinghigher.wav` に配置し、ルートから `python3 Dance/checks/analyze-audio.py` を実行してください（NumPyが必要）。macOSでは `afconvert Dance/assets/digitalstar.mp3 /tmp/dance-digitalstar.wav -f WAVE -d LEI16` で変換できます。

署名を再生成する場合は `python3 Dance/checks/make-signatures.py` を実行します（上記のPCM WAVとNumPyが必要）。
